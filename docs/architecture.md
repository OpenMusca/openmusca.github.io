# Architecture

Status words: **works** = running on a real device; **experimental** = built and partly tested, not for users;
**planned** = designed, not implemented.

## Layers

```
BootROM -> SPL (stock, never touched)
              |  slot register 0x02390024
              +-> slot A: stock U-Boot -> stock kernel -> stock userland   (recovery path)
              +-> slot B: our U-Boot  -> kernel B (stock copy today)       (experimental)
                                            |
                          rcS -> /opt/system_init.sh  (the M1 hook)
                                            |
                              supervisor -> muscad -> UART3 -> feeder MCU
                                               |
                                               +-> MQTT -> broker -> Home Assistant
```

### A/B slots

The flash holds two copies of U-Boot and kernel (`mtd3`/`mtd7` slot A, `mtd4`/`mtd8` slot B). The stock SPL chooses a slot
from a register. Our scheme never marks slot A as bootable-and-final, so a warm reboot of A passes through our U-Boot in
B, and any power cut returns to the untouched stock slot A. A fail-safe by construction: the stock chain is never
overwritten. Boot stage markers written to a register that survives a warm reset let you see how far a boot got from
Linux, without a UART.

### Our U-Boot in slot B (experimental)

Built from the public Axera SDK U-Boot 2020.04 plus our patches (`tools/build/patches/uboot/`, GPL-2.0-or-later):
XINCUN SPI-NAND support, A/B selection, a fixed FIT unpack, no environment writes during boot, checked flash reads.
It currently boots a copy of the stock kernel from `mtd8`.

### Kernel variants (experimental)

| Variant | State |
|---|---|
| stock 4.19.125 (slot A) | works; the vendor modules load |
| our 4.19.125 build with the XINCUN patch | builds; boots from slot B with the stock-copy path; vendor `ax_*` modules need kernel-config parity first |
| 4.19.x CIP (longer-term-support patches) | builds, not yet booted on a device |
| feeder-only kernel without the camera/NPU drivers | design; reduces closed-source dependencies |

The vendor Wi-Fi module is refused on any kernel other than the stock one (different `sk_buff` layout, it would corrupt
packets). Our own `8733bu` module, built from the Realtek GPL source, is shipped per kernel release and verified by
SHA-256 before it is loaded.

### The M1 hook (works)

M1 changes no flash partition. `/opt` is a writable UBIFS volume and the stock `rcS` runs `/opt/system_init.sh` if it
exists. The package installs our script there. It:

1. loads a verified Wi-Fi module when needed and brings up Wi-Fi and DHCP the way stock does (reusing the stock-generated
   Wi-Fi credentials, kept mode 0600 and never logged);
2. starts NTP, optionally dropbear (SSH, key-only), then `supervisor`;
3. never starts the vendor `ctrl`, `cloud`, `agora`, `logUpload`, `ble`, `media` or watchdog programs;
4. counts boots and watches `muscad`. After 3 boots without a stable `muscad` (stable = 5 minutes), 5 restarts in 10
   minutes, or no IPv4 address in 300 s, it runs the stock start-up instead and re-enables telnet (**boot guard**).
   `/opt/musca/DISABLE` forces the stock path.

### `muscad` and `supervisor` (Rust, `agent/`)

Two static armv7 (musl) binaries, built reproducibly in a pinned Docker image. Design notes: `agent/DESIGN.md`.

| Crate | Role |
|---|---|
| `musca-core` | config, scheduler, MQTT with retained availability and last will, Home Assistant discovery, clock/NTP handling, device id |
| `musca-p592` | the P592: MCU framing and CRC, UART link, feed with safety limits, LED, decoding, HA entity table |
| `musca-camera` | stub (planned) |
| `musca` | the binaries `muscad` and `supervisor` |

`supervisor` pets `/dev/watchdog` and respawns `muscad`; it keeps a bounded crash log (last words, signal sender,
process list) on flash. `muscad` is the only process that opens the MCU serial port; the MCU feeds on its own
schedule whether or not `muscad` runs. Details of the topics and entities: [Home Assistant](home-assistant.md).

### Own userland (planned)

`br2-musca/` is a Buildroot external tree for an own root filesystem (replacing the vendor initramfs), so the full
image contains no vendor userland. Not part of the M1 install.

### Updates (planned)

Signed update bundles applied with SWUpdate in an A/B scheme with a U-Boot boot counter and automatic roll-back,
published on a mirror and on GitHub releases. Keys are generated by the maintainers; the repository holds only a
placeholder public key. Until this exists, updates are manual: build, verify the checksum, install. See
[SECURITY.md](security.md).

## Design rules

- Local first: no vendor cloud, no outbound connections except NTP and (planned) the update mirror.
- Every step has a documented way back to stock; destructive steps need an explicit decision by the owner of the device.
- One owner of each resource: one process on the MCU serial port, one hook on `/opt/system_init.sh`.
- No vendor code or binaries in this repository or in published images ([legal](legal.md)).
